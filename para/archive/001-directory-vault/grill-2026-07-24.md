# Grill: file-only vault via the File System Access API

The project started as "bundle Balaur in Tauri for cross-platform desktop/mobile" and
converged, through grilling, on the underlying motivation: a real-folder vault. The shell
question was evaluated (Tauri, Electron, Neutralino, Bun-binary) and deferred; the v1
deliverable is the vault capability itself, in the browser, with IndexedDB removed.

## Decisions made

- **Primary motivation is the real-folder vault**: vault data lives as plain files in a user-chosen directory, syncable with Syncthing/Dropbox/git and editable in any editor. Store distribution, COOP/COEP persistent-index unlock, and native integrations are not drivers for this project.
- **Desktop-only v1**: mobile is a separate later project with limited features, not a scope item here. This nullifies Tauri v2's main forward argument (shared mobile codebase).
- **File System Access API (`showDirectoryPicker`) as the sole vault adapter**: a new `DirectoryVault` implements the existing async `VaultStore` contract over a `FileSystemDirectoryHandle` (list via `values()`, read via `getFile()`, write via `createWritable()` with the existing `content-hash.js` expected-hash precondition). This is the "browser directory access" option explicitly reserved in `docs/architecture.md:105`. No build step, no toolchain, no §1 violation.
- **Incompatible browsers get a hard gate**: Firefox and Safari (no `showDirectoryPicker`) see a full-screen "Balaur needs a Chromium-based desktop browser" message. No fallback adapter. Feature detection also requires `crypto.subtle` (secure context; GitHub Pages HTTPS and localhost dev already satisfy it).
- **IndexedDB is removed entirely**: delete `storage/indexeddb-vault.js` and the one-time `localStorage` first-run migration in `app.js`. `MemoryVault` (test adapter) and `FsVault` (Node reference/tooling) stay. AGENTS.md §5 boot model and §13 browser-pending list are updated in the same change.
- **Re-pick the vault folder every launch**: zero persistence anywhere; no stored directory handle, no handle locker. Multi-vault is free (pick a different folder). A handle locker (~30 lines, one IDB key storing the handle, never data) is a known additive option if the daily click becomes annoying — YAGNI for v1.
- **Existing data migration is manual and one-time**: export the whole-space `.balaur.json` from the currently deployed IndexedDB version *before* the switch, then import it into the picked folder on the new version (the version-2 backup import already validates into a staging vault). Single-user reality; satisfies §17 "no silent orphaning".
- **Test seam**: `DirectoryVault` takes a `FileSystemDirectoryHandle` in its constructor. Headless contract tests pass an OPFS handle (`navigator.storage.getDirectory()` — same interface) so the suite runs under the `browser-check` skill without driving the native picker; the real-picker flow is manual smoke (pick, reload + re-pick, external-change reconciliation).
- **Toolchain adoption is a separate project**: Node/Bun as a runtime is rejected; TypeScript-as-dev-only-checking (JSDoc + `tsc --noEmit`, zero build step) may become `002-typed-toolchain` later. This project ships vanilla JS under the current constraints.

## Explicitly ruled out

- **Mobile app in this project**: separate later project with limited features.
- **Tauri shell**: would rewrite the Node-verified `FsVault` in Rust (new language, new bug surface, tests don't transfer); three untested webview engines vs the Chromium the `browser-check` skill verifies; mobile advantage nullified by mobile being out of scope.
- **Electron shell for v1**: legitimate option (reuses `FsVault` in the Node main process, single Chromium engine, Obsidian precedent) but 100MB bundle, npm packaging toolchain, IPC security surface; deferred until the vault UX is validated.
- **Neutralino shell for v1**: best-fitting shell if one is ever wanted (JS-only, ~2MB binary, single vendored client file fitting the `vendor/` provenance pattern, native fs + directory dialog) but WebKitGTK would run untested on the maintainer's own NixOS box and the project has small-community maintenance risk; deferred.
- **Bun as a single-binary runtime**: gives a server, not a window; either opens a browser tab (no app feel, no secure-context guarantees) or reinvents Electron with more glue. Loses on every axis that matters here.
- **OPFS as vault storage**: origin-private, not a real folder, not syncable; serves the persistent-index goal, not the real-folder goal. (Used only as a test double for the directory handle.)
- **Persisted directory handle / handle locker in v1**: re-pick every launch instead; KISS and zero invalidation edge cases.
- **Firefox/Safari fallback adapter**: hard incompatibility gate instead; one adapter, one engine.
- **Build pipeline or TypeScript sources in this project**: separate project if ever; the shipped artifact stays build-less.

## Open questions (deferred)

- **Desktop shell, if ever** (Neutralino vs Electron vs none) — depends on whether an app artifact/distribution is wanted after the DirectoryVault UX is validated; user decides. Note: WebKitGTK/WKWebView lack `showDirectoryPicker`, so any future shell on Linux/macOS brings its own fs adapter (additive under the `VaultStore` contract).
- **Typed toolchain** (JSDoc + `tsc --noEmit`, dev-only) — separate project `002-typed-toolchain` if wanted; user decides. `app.js` is 1831 lines with zero type annotations today.
- **Handle locker** — revisit only if daily re-pick proves annoying in lived use; user decides.
- **Persistent index** (OPFS SQLite) — doubly deferred: needs large-vault justification and a secure-context story; not v1.
- **Multi-device sync behavior** (Syncthing pulling under re-pick + warm reconciliation) — validated during implementation via manual smoke, not designed up front.

## Summary for downstream

Build `DirectoryVault`, a `VaultStore` adapter over a `FileSystemDirectoryHandle` from `showDirectoryPicker({mode:'readwrite'})`, and make it the only vault: delete `IndexedDbVault` and the localStorage first-run migration, and gate incompatible browsers (no `showDirectoryPicker` or no `crypto.subtle`) with a full-screen incompatibility message. Boot becomes: vault gate → user picks folder → DirectoryVault opens → workspace loads; the folder is re-picked every launch (no persisted handle). The constructor takes the handle so headless contract tests run against an OPFS handle via the `browser-check` skill; the real picker flow and external-change reconciliation are manual smoke. Constraints: vanilla JS, no build step, no new dependencies; existing data migrates by one-time whole-space `.balaur.json` export/import. Ship with ADR-0004 and updates to `docs/architecture.md`, `docs/life-data.md`, `README.md`, and AGENTS.md §5/§13.
