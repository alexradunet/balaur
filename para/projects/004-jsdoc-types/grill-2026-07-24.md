# Grill: JSDoc type enforcement for the Balaur codebase

## Status: parked idea

Recorded as an idea, not an active project. It proceeds only if Balaur adopts a JS
toolchain (a Bun- or Node-based workflow). If the app stays a pure-static,
no-toolchain site, this stays an idea. A dev-time enabler already exists: TypeScript
5.9.3 is installed in the `nixpi-dev-os` NixOS environment (commit `abd25de`), so
`tsc --checkJs` is available with no package manifest in this repo. Paused behind
project 003 (file-unified node model), which is actively refactoring the storage
layer and notes; resume after 003 merges to main.

## Decisions made

- **Goal (Q1):** catch wrong-shape bugs at module boundaries (a) and null/undefined
  landmines (b), enforced at edit time. Living documentation is a side effect, not
  the goal; CI gating is a separate, later question.
- **Checker hosting (Q2):** option C — TypeScript provided by the OS environment
  (the `nixpi-dev-os` flake), not a package manifest in this repo. Keeps the shipped
  app and the repo dependency-free (AGENTS.md §1/§13) while giving a real, pinned,
  offline checker. `tsc` 5.9.3 is installed and on PATH system-wide.
- **Rollout scope (Q3):** storage core first, with gradual per-file opt-in via
  `// @ts-check` (tsconfig `checkJs: false` by default). The checker is useful from
  the first annotated file and never blocks on un-annotated files.
- **Strictness (Q4):** full `strict: true` for opted-in files (includes
  `strictNullChecks` and `noImplicitAny`, the flags that make goals a and b
  catchable). A soft subset was rejected as ceremonial.
- **tsconfig skeleton (accepted):** `target es2022`, `module esnext`,
  `moduleResolution bundler`, `lib [es2022, dom, dom.iterable]`, `allowJs true`,
  `checkJs false`, `strict true`, `noEmit true`; `include ["**/*.js"]`,
  `exclude ["vendor/**", "node_modules/**"]`. `noEmit` is non-negotiable: the app
  runs the original source, never compiled output.

## Explicitly ruled out

- **Bun single-binary deployment:** Bun has no GUI/webview (it yields a headless
  server binary, not a desktop app), it strips rather than checks types (zero
  contribution to the goal), the app is already a cross-platform installable PWA,
  and a compiled binary is a build pipeline that AGENTS.md §1 forbids. If a native
  desktop app is ever wanted, Tauri (already on the radar, §14) is the right tool,
  as a separate project.
- **devDependency package.json (option A) and floating `npx tsc` (option B):** both
  compromise the no-manifest / no-CDN identity; the Nix-provided checker (C) avoids
  both. Revisit only if the project migrates to a Bun/Node toolchain.
- **Soft strictness subset** (`noImplicitAny` off): holes in the protection.
- **Big-bang `checkJs: true`** across all 57 files: a wall of errors on a zero-JSDoc
  codebase before any value.
- **Typing all 57 files / `app.js` now:** `app.js` (1,831 lines, "do not
  mass-format") and the DOM-heavy buckets are deferred; storage core is the
  high-value, tested, shape-dense target.

## Open questions (deferred)

- **Toolchain direction (gating):** does Balaur adopt a Bun/Node toolchain? If not,
  this stays an idea. User decides.
- **CI gating:** should the check run in GitHub Actions? Downstream of the hosting
  decision; a Nix-only checker is awkward in CI, which is one reason a future
  Node/Bun toolchain might change the approach.
- **AGENTS.md amendment + ADR:** at implementation time, record that type checking is
  dev-time, `noEmit`, OS-provided, and that the no-build/no-manifest rule governs the
  shipped app. Coordinate with project 003's ticket 05, which also edits AGENTS.md.
- **Exact storage file order**, and whether to also type `ai/generated-operations.js`
  (shape-heavy) alongside storage.
- **Re-scope after 003:** storage/ will include new `note-catalog.js` and
  `note-repository.js`; annotate the final storage/ in one coherent pass.

## Why paused behind project 003

Project 003 (file-unified node model, ADR-0004) is actively refactoring how notes and
files are saved: it adds `storage/note-catalog.js` and `storage/note-repository.js`
and edits `app.js`, `ai/generated-operations.js`, and the docs. It keeps the existing
storage modules byte-for-byte unchanged (so no hard line conflict), but annotating
storage now means re-work to cover the new note modules afterward, and both projects
edit AGENTS.md. 003 is further along (implementing ticket 1 of 5) and owns the storage
layer's near-term evolution; sequencing behind it lets us annotate the final storage/
once.

## Summary for downstream

Balaur wants edit-time JSDoc type enforcement to catch wrong-shape bugs and
null/undefined landmines, using full `strict` TypeScript with gradual per-file
`// @ts-check`, storage core first, and a Nix-provided `tsc` (5.9.3, already
installed) so the repo stays dependency-free and `noEmit` keeps the shipped app
unchanged. Bun single-binary was rejected. This is parked as an idea contingent on
adopting a Bun/Node toolchain, and paused behind project 003; when resumed, re-scope
to the post-003 storage/ (note modules included), add the tsconfig.json above, write
the AGENTS.md §13 amendment plus a small ADR, and annotate storage file-by-file.
