## Why this matters

Balaur ships a Johnny Decimal (JD) subsystem: numeric area/category/item codes,
a validation dialog, `goToJD` lookup, `<!-- orbit:jd -->` markers treated as
structure, and a sidecar `johnnyDecimal` index. JD is heavier than the app
needs, has no lifecycle (capture → project → archive), and forces a
dialog/validation layer. The settled direction (grill 2026-07-24) reframes the
app as **"Obsidian + AI + Canvas as the operating layer"**: the editable spatial
canvas graph *is* the knowledge layer, and the AI reads/traverses it as memory.

Landing this removes the JD machinery entirely and replaces it with: four light
hub canvases off Home (Inbox · Projects · Wiki · Archive); node typing through
three *existing* channels (sidecar `kind`, inert body markers, entity
frontmatter); standard edge `label`s as a relation *convention*; a read-only AI
graph-traversal memory layer; a Today-view journaling feature; and a
self-teaching starter. Everything stays standards-compliant JSON Canvas 1.0 and
file-canonical. Existing JD vaults keep working (their data is already valid
JSON Canvas); there is intentionally no migration.

## Decisions (resolved open questions from the grill)

Each grill open question is settled here with a KISS choice. Record these in the
ADR and docs.

1. **Note-kind marker name → `reference`** (not `wiki`). It names the node's
   role (a durable reference page covering PARA Areas+Resources content), not
   its location. Markers: `<!-- orbit:inbox -->` and `<!-- orbit:reference -->`.
2. **Lifecycle edge label → `filed-to`** (not `promoted-to`). Matches the
   Inbox/processing framing. Relation vocabulary (convention only, never
   enforced): `part-of` (structural), `relates-to` (associative), `filed-to`
   (lifecycle: inbox→Project/Wiki, Project→Archive). `AI output` stays reserved.
3. **One-line summary convention → derived from existing content, no new field.**
   A node's summary is its heading/title: `nodeTitle(node)` for structure; for a
   text note, the first `# Heading` if present, else the first non-empty,
   non-marker body line, truncated to ~120 chars. The starter demonstrates this
   by giving every example node a clear heading + one-line description. No new
   marker field, no frontmatter addition (standards-compliant, KISS).
4. **AI traversal depth bound → 2 canvas hops from Home, capped at 60 nodes.**
   Home = depth 0, hubs = depth 1, canvases directly under a hub (e.g. projects)
   = depth 2. The digest also lists each visited node's outgoing **labelled**
   edges. This covers the whole starter and orients the AI without exploding
   context. Both limits are named constants (`GRAPH_MEMORY_DEPTH=2`,
   `GRAPH_MEMORY_NODE_CAP=60`).
5. **Journal placement UX → explicit "Place on canvas" button** (not automatic).
   The Today daily-note panel has a button that places a standard `file` node
   for the viewed date's journal onto the **currently open canvas**, then
   switches to Canvas view and reveals the node. Automatic placement would
   clutter and surprise. Journal nodes are then linkable like any node.
6. **Today panel date navigation → prev-day / Today / next-day** + editable body
   + place-on-canvas. No calendar picker (YAGNI). The panel defaults to today;
   `‹`/`Today`/`›` move the viewed date; the textarea edits that date's journal
   body (debounced create-or-update); a small status line shows save state.
7. **Starter example content → see Step 4** (Home + 4 hubs + one Inbox note
   `filed-to` a Project canvas that holds a seeded task; two Wiki reference pages
   `relates-to` each other plus a placed journal node; one dormant item under
   Archive). Bundled-widget seeding is retained.
8. **Dormant/archive node color → `#6c757d`** (muted grey), a named constant
   `DORMANT_NODE_COLOR`. JSON Canvas permits `#rrggbb`, so this is
   standards-compliant and visually distinct from the six preset colors. The
   archive action sets this color when reparenting under the Archive hub.
9. **Sidecar version → stay at `SIDECAR_VERSION = 2`.** Do **not** bump it.
   `parseSidecar` rejects `version !== 2`, so bumping would break every existing
   vault and backup. Instead make `johnnyDecimal` optional and stripped, and
   `kind` optional — old sidecars load and are cleaned on read.
10. **Component-card / widget interaction → none.** Cards (`cards/*.md`) and
    widgets (`widgets/*.html`) are matched by path pattern; the new node kinds
    (inbox/reference text notes, hub/project canvases, journal `file` nodes) do
    not collide. Journal file nodes get a small dedicated render branch so they
    are recognizable instead of falling through to the generic FILE card.

async addPlacement(localDate, canvasId, geometry = {}) {
  const path = journalPath(localDate);
  const stat = await this.vault.stat(path);
  if (!stat) throw new SchemaError(`Journal not found: ${localDate}`, { code: "JOURNAL_NOT_FOUND" });
  const canvasPath = this.canvasPathFromId(canvasId);
  if (!canvasPath) throw new SchemaError(`No canvas path for id: ${canvasId}`, { code: "CANVAS_NOT_FOUND" });
  const canvasStat = await this.vault.stat(canvasPath);
  if (!canvasStat) throw new SchemaError(`Canvas not found: ${canvasPath}`, { code: "CANVAS_NOT_FOUND" });
  let doc;
  try { doc = JSON.parse(await this.vault.read(canvasPath)); }
  catch (err) { throw new SchemaError(`Invalid canvas document: ${canvasPath}`, { code: "CANVAS_INVALID", cause: err }); }
  if (!isCanvas(doc)) throw new SchemaError(`Invalid canvas document: ${canvasPath}`, { code: "CANVAS_INVALID" });
  const g = { x: 40, y: 40, width: 320, height: 200, ...geometry };
  const nodeId = geometry.id || `node-${localDate}`;
  if (doc.nodes.some((n) => n.id === nodeId) || doc.edges.some((e) => e.id === nodeId)) throw new SchemaError(`Canvas id already exists: ${nodeId}`, { code: "CANVAS_ID_DUPLICATE" });
  doc.nodes.push({ id: nodeId, type: "file", file: path, x: g.x, y: g.y, width: g.width, height: g.height, ...(g.color ? { color: g.color } : {}) });
  if (!isCanvas(doc)) throw new SchemaError(`Invalid canvas document: ${canvasPath}`, { code: "CANVAS_INVALID" });
  const content = JSON.stringify(doc, null, 2) + "\n";
  await this.vault.write(canvasPath, content, { expectedHash: canvasStat.hash });
  await this.indexer.indexFile(canvasPath, content, {});
  return { canvasId, nodeId, canvasPath, path };
}

```js
const GRAPH_MEMORY_DEPTH=2, GRAPH_MEMORY_NODE_CAP=60;
function graphMemoryDigest({maxDepth=GRAPH_MEMORY_DEPTH,nodeCap=GRAPH_MEMORY_NODE_CAP}={}){
  const lines=[],visited=new Set();let nodeCount=0;
  const edgeLabelsFrom=(doc,nodeId)=>(doc.edges||[]).filter(e=>e.fromNode===nodeId&&e.label&&e.label!=="AI output").map(e=>{const to=(doc.nodes||[]).find(n=>n.id===e.toNode);return to?`${e.label} → ${nodeTitle(to)}`:null;}).filter(Boolean);
  const visit=(canvasId,depth)=>{
    const record=workspace.canvases[canvasId];
    if(!record||visited.has(canvasId)||depth>maxDepth)return;
    visited.add(canvasId);
    const kind=canvasKind(record);
    lines.push(`${"  ".repeat(depth)}${record.title}${kind?` (${kind})`:canvasId===workspace.rootId?" (home)":""}`);
    for(const node of record.document.nodes||[]){
      if(nodeCount>=nodeCap)return;
      if(node.type==="group")continue;
      nodeCount++;
      const marker=noteKind(node)?`[${noteKind(node)}] `:node.type==="file"?"[file] ":"";
      lines.push(`${"  ".repeat(depth+1)}- ${marker}${nodeSummary(node)}`);
      for(const rel of edgeLabelsFrom(record.document,node.id))lines.push(`${"  ".repeat(depth+2)}${rel}`);
      const sub=subcanvasIdFromNode(node);
      if(sub)visit(sub,depth+1);
    }
  };
  visit(workspace.rootId,0);
  if(nodeCount>=nodeCap)lines.push(`(truncated at ${nodeCap} nodes)`);
  return lines.join("\n");
}
```

## Maintenance notes

- **Relations are convention, not schema.** If someone later wants enforced
  relation types, that is an architecture change (it would make Balaur a
  proprietary Canvas dialect, violating AGENTS.md §4.1). Keep labels unvalidated.
- **Sidecar `kind` is app metadata.** It may grow new values (e.g. a future
  area), but `parseSidecar` sanitizes unknown values by deletion, so a hand-edited
  or future sidecar can never make the workspace unloadable. If you add a kind,
  update `canvasKind`, `defaultCanvasIcon`, the starter, and the docs together.
- **The graph memory digest is synchronous and index-backed.** If vault-backed
  body summaries are ever wanted, the digest must become async and bounded; do
  not let it read the vault per node during render (AGENTS.md §5).
- **Journal placement reuses the task-placement contract.** If `addPlacement`
  semantics change in `FileTaskRepository`, keep the journal copy consistent (or
  extract a shared helper then).
- **No migration is intentional.** Old JD vaults keep their `<!-- orbit:jd -->`
  markers as inert text and their canvases as valid JSON Canvas; `normalizeWorkspace`
  and `parseSidecar` strip legacy sidecar JD on load. Do not add a JD→graph
  migrator without an accepted architecture change.
- **Reviewer should scrutinize:** the sidecar schema diff (backward compat with
  existing v2 sidecars and backups), the starter's canvas validity (edges vs
  seeding order), the journal panel's single-file async read (not per-card), and
  that the AI changes add context only (no new operation type, no relaxed
  validation, no autonomous write).

  AI navigation suffice for v1); automated archive action (manual/explicit per
