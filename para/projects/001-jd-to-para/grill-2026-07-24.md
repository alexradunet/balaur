# Grill: Replace the Johnny Decimal subsystem with a graph-first knowledge + AI-memory model

## Decisions made

- **Full subsystem replacement, not a starter-content swap.** A graph/PARA app that still ships JD machinery is a half-migration; the coherent end-state removes JD entirely (dialog, `goToJD`, markers-as-structure, sidecar `johnnyDecimal`).
- **Product framing: "Obsidian + AI + Canvas as the main operating layer."** The editable spatial canvas graph *is* the knowledge layer; the AI reads/traverses it as memory. Differentiators vs Obsidian: the canvas is the *editable* graph (Obsidian's graph view is a passive picture), and AI is *native* to the graph (not a bolted-on plugin).
- **Organizing model: graph-first.** Hubs are light entry canvases, not folders; structure emerges from labelled edges. Buckets are entry points only, rejecting folder-hierarchy as the primary model (it fights the canvas-as-editable-graph medium).
- **Hub set: four hubs off Home — Inbox · Projects · Wiki · Archive.**
  - **Inbox**: capture queue of quick notes *pending processing* (GTD-style, trends toward empty). More general than "Ideas"; carries a processing discipline.
  - **Projects**: committed active efforts with a finish line; canvases holding task file-nodes, notes, sub-canvases.
  - **Wiki**: durable reference + responsibilities; merges PARA's Areas + Resources for KISS. The "Life Wiki / Life Archival." Interlinked.
  - **Archive**: dormant/completed; lifecycle terminal.
- **Home = the root canvas**, the canonical AI + user entry point. No new sidecar field for Home (KISS).
- **Node-type vocabulary, via three existing channels (no new mechanism):**
  - canvas kinds (sidecar `kind`): `hub`, `project`
  - note kinds (inert body marker `<!-- balaur:TYPE -->`): `inbox` (capture pending processing), `reference` (durable wiki page; covers Areas+Resources content)
  - entity files (frontmatter `balaur-type`): `task`, `journal` (both already exist)
  - `ai-card` (existing marker). JD `area`/`category`/`item` kinds are removed.
- **Relation labels = standard edge `label`s, convention not enforced schema** (an enforced enum would be a proprietary Canvas dialect, forbidden by AGENTS.md §4.1): `part-of` (structural), `relates-to` (associative), `filed-to` (lifecycle: inbox→Project/Wiki, Project→Archive). `AI output` stays reserved (AI code already filters on it). Edge `label` is already accepted by the validator, rendered, and used.
- **Idea/Project distinction = commitment.** Inbox note = uncommitted potential (a note, no tasks); Project = committed effort with a finish line (a canvas, has tasks). Lifecycle via the `filed-to` edge. Crisper than PARA's fuzzy Project/Area/Resource boundary; mis-filing is cheap to fix.
- **AI memory layer = read/traverse + confirmed writes only.** Traverse from Home via labelled edges + type markers + one-line summaries, bounded depth; propose changes only through the existing confirmed AI-operation flow (AGENTS.md §10). No autonomous mutation, auto-tagging, auto-linking, or roaming. Extends existing machinery (inert markers, edge-derived context assembly that resolves file bodies, balaur-ids, cycle detection); the new work is the Home entry point, consistent node typing, a tiny relation vocabulary, a summary convention, and a depth bound.
- **Journaling is a temporal feature, not a hub.** Daily-note panel in the Today view (the daily driver) + canonical date-indexed files (existing `FileJournalRepository`, `journal/YYYY/YYYY-MM-DD.md`) + journal nodes placeable/linkable in the graph (can live under Wiki or link from a project). Accessed by date, not a spatial hub. Storage + index already exist and are tested; the **UI is the new work**.
- **Archive mechanics:** reparent the node/portal under the Archive hub + set a dormant node color; never delete; manual and explicit.
- **Migration: none for v1.** Existing JD data stays valid JSON Canvas (canvases + text nodes); JD UI and `goToJD` are removed; `<!-- balaur:jd -->` markers remain harmless inert text; `normalizeWorkspace` strips legacy `johnnyDecimal` on load. Users can export a whole-space backup (still valid) or load the new starter.
- **Navigation:** remove the JD dialog and `goToJD`; rely on the existing canvas-tree sidebar + portals.
- **Sidecar schema:** drop `johnnyDecimal`; add optional canvas `kind` (`hub`/`project`) as app metadata; `normalizeWorkspace` strips legacy `johnnyDecimal` gracefully so old sidecars load.
- **Starter content:** a self-teaching graph replacing "Alex, age 30": Home (root) + four hub portals + example nodes that demonstrate the pipeline (an inbox note `filed-to` a Project canvas containing a task; reference pages `relates-to` each other under Wiki; a journal note; an archived item under Archive), with labelled edges and one-line summaries. Bundled widget seeding retained.

## Explicitly ruled out

- **Keeping JD / half-migration:** incoherent; JD's numeric overhead is exactly what we're escaping, and it has no lifecycle, archive, or capture bucket.
- **Starter-content-only swap (option 2):** ships a half-state where a graph starter fights surviving JD UI.
- **Folder/bucket-hierarchy as the primary model:** fights the canvas-as-editable-graph medium.
- **Pure graph/MOC as the top level with no scaffold:** blank-canvas paralysis for new users. MOC behavior is encouraged *inside* hubs via example content, not as the entry model.
- **Areas + Resources as separate top-level hubs (IPARAJ):** PARA's fuzziest boundary; merged into Wiki for KISS. Recoverable within Wiki later via a marker/edge if ever needed (YAGNI).
- **Journals as a dedicated top-level hub:** temporal and high-volume; better browsed by date than by a spatial canvas. Demoted to a feature.
- **Migration of existing JD vaults:** pre-1.0, single-user, experimental; YAGNI; data stays valid.
- **Autonomous AI writes / auto-tagging / auto-linking / AI roaming:** violates the AGENTS.md §10 security boundary; AI proposes, user confirms.
- **Persistent index / SQLite, sync, recurrence:** out of scope for canonical-files-only v1 (AGENTS.md §1).
- **Title-search "jump to node/canvas":** out of scope for v1 (sidebar + portals + AI navigation suffice).
- **Enforced enum validation of edge labels / node types:** would be a proprietary Canvas dialect (§4.1); convention only.

## Summary for downstream

Replace the Johnny Decimal subsystem with a graph-first knowledge model: the app becomes "Obsidian + AI + Canvas as the operating layer," where the editable spatial canvas graph is the knowledge layer and the AI reads/traverses it as memory. The top level is four light hub canvases (Inbox · Projects · Wiki · Archive) hanging off Home (the root canvas); journaling is a temporal feature (Today-view daily-note panel + existing date-indexed journal files + placeable/linkable journal nodes), not a hub. Nodes are typed through three existing channels (sidecar `kind` for hub/project canvases, inert `<!-- balaur:TYPE -->` markers for inbox/reference notes, frontmatter `balaur-type` for task/journal files), and relations use standard edge `label`s (part-of / relates-to / filed-to) as convention, not enforced schema. The AI memory layer extends the existing edge-derived context assembly: traverse from Home via labelled edges + type markers + one-line summaries, bounded depth, proposing changes only through the confirmed AI-operation flow (no autonomous writes). Deliverables: remove JD (dialog, goToJD, markers-as-structure, sidecar johnnyDecimal); add the hub/graph model, node typing, relation conventions, Home entry, and the journaling UI; ship a self-teaching starter; write ADR 0003; rewrite the affected docs. No migration for existing JD vaults (data stays valid JSON Canvas). Everything must remain standards-compliant JSON Canvas and file-canonical.
