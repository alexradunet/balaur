The test pins the placed node's keys to exactly `["file","height","id","type","width","x","y"]` (`note-repository.test.js:84-92`), proving no custom fields or `orbit-id` leak onto the node. No custom node types are introduced.
- **AI security boundary (§10):** `ai/` diff is empty. `isAICard`/`parseAICard` now read the catalog body (`app.js:751-756`), but the operator still proposes allowlisted operations through the unchanged `applyCanvasOperations`/`validateGeneratedOperation` path; the AI output is a note body rendered via `markdownToHTML` (`app.js:991`). Debouncing (`scheduleAICard`), queued reruns (`state.pending`), and cycle detection (`aiCardHasCycle`) are untouched.
- **Synchronous render (§5):** the note branch reads only `noteCatalog.getByPath`/`getFallbackByPath` (a preloaded projection) — no `await`, no per-card vault read (`app.js:984-994`). `nodeAIContent` resolves the note body synchronously from the catalog (`app.js:771`).
- **Canonical-file-first writes (§7):** `createNote` writes the `.md` with `expectedHash:null` then reindexes (`note-repository.js:69-71`); `addPlacement`/`_removePlacementAtPath` write the canvas under `expectedHash: stat.hash` then reindex (`:101,121`); `updateNote` checks the catalog's last-known hash against the vault hash and throws `ConflictError WRITE_CONFLICT` on mismatch before writing under `stat.hash` (`:142-148`); `deleteNote` removes placements, then the file under `stat.hash`, then `indexer.removeFile` (`:167-172`). Reindex-after-write and catalog reconcile follow every write.
- **Confirmed test seams:** notes have no `orbit-id` (test at `note-repository.test.js:84-92`); note placements stay out of the disposable index (regression pin at `:236-258` asserts `allPlacements().length === 0` and `placementsForEntity(path).length === 0` while drain/delete still work); drain/delete resolve placements by canvas path scan (`deleteNote:160` reads `catalog.getByPath(path)?.placements`; `_removePlacementAtPath:106-123` scans the canvas document). The three guard modules are byte-for-byte unchanged.
- **Code standards:** modules are cohesive, named helpers are specific and greppable, errors carry codes (`CANVAS_NOT_FOUND`, `CANVAS_INVALID`, `CANVAS_GEOMETRY_INVALID`, `CANVAS_ID_DUPLICATE`, `NOTE_NOT_FOUND`, `WRITE_CONFLICT`), validation sits at the storage boundary, and the provenance comments tie the design back to ADR-0004 and the widget/task/component-card precedents.

Findings (all `[judgement]`; none break a documented rule):

- [judgement] `storage/note-catalog.js:76-140` — Long function: `rebuild()` is ~64 lines, over the 4–20 guideline. It mirrors `widget-catalog.js` verbatim (the precedent the plan mandated cloning); an extraction shared with the widget catalog would be a cross-cutting refactor, not a defect introduced here.
- [judgement] `storage/note-repository.js:78-102,106-123,125-136` — Duplicated Code (Fowler #2): `addPlacement`/`_removePlacementAtPath`/`removePlacement` are near-clones of the task, journal, and component-card repositories. Sanctioned by the established per-repository pattern; a shared placement mixin would touch all four repositories and is out of scope.
- [judgement] `storage/note-repository.js:78` — `addPlacement` does not stat the note path or throw `NOTE_NOT_FOUND` before placing, so it can create a dangling `file`-node for a missing note path (diverging from the journal precedent at `journal-event-repository.js:65-66` which stats the placed entity). The catalog surfaces the dangling reference as `NOTE_FILE_MISSING` (`note-catalog.js:124-125`); tracked as a known follow-up, not a defect introduced here.
- [judgement] `storage/note-repository.js:91` — the geometry error ("Placement geometry must use integers with positive dimensions") states the expected shape but not the offending field/value; the code standard asks errors to include the offending value. Copied verbatim from `component-card-repository.js`.
- [judgement] `storage/note-repository.js:144` — `updateNote`'s `known &&` guard skips the conflict check when the catalog holds no baseline entry for the path, so a behind-the-back write to a note the catalog never saw would go undetected. In normal flow the repository reconciles the catalog after every create/update/delete, so the baseline exists; not reachable through the repository's own API.
- [judgement] `app.js:1205-1234` — `addNode` is ~30 lines and `seedGraphStarterEntities` (`app.js:113-153`) ~40, over the 4–20 guideline. Both are cohesive (a preset data table plus two branches; a seeds table plus loop that avoids ten duplicated try/catch blocks) and consistent with `app.js`'s established dense style; splitting would be speculative (YAGNI).
- [judgement] `app.js:611-635,1435-1445` — Duplicated Code: the note update trio (`updateNoteBody`/`scheduleNoteUpdate`/`flushNoteUpdate`) and `deleteNoteEverywhere` deliberately mirror the task discipline (`updateTask`/`scheduleTaskFieldUpdate`/`flushTaskFieldUpdate`/`deleteTaskEverywhere`). Appropriate for now: two call sites with divergent internals (id + patch-merge vs path + whole-body replacement; `lifeIndex` placements vs catalog placements), so a shared extractor would be Speculative Generality (#9).
- [judgement] `app.js:1898` — the `runAICard` output lookup uses `.find(edge => … label==="AI output")`, which returns the FIRST matching edge. In a pre-existing dev vault that still has a legacy text-node `AI output` edge (pre-ADR-0004), that stale edge's target fails the `type==="file" && isNotePath` test, so `outputNode` is undefined and the create branch runs again on every run — and because `.find` keeps returning the stale edge first, the new file-backed output is never matched on later runs either. The result is unbounded accumulation of file-backed outputs + `AI output` edges for that card, not a one-time duplicate. This affects ONLY legacy dev vaults (the hard cut regenerates them with no migration; a fresh/regenerated space seeds no AI outputs, and the supported path reuses stably: first run creates the file-backed output + edge, later runs match it and `updateNote` in place). Accepted hard-cut consequence; if legacy dev vaults matter, prefer `findLast` or filter the edge search to targets satisfying `type==="file" && isNotePath`.
- [judgement] `.pi/skills/browser-check/scripts/browser-check.mjs:371,373` — stale assertion: the smoke check reads `lastText: last?.text ?? ""` and asserts `info.lastText.includes("New thought")`. Double-click now creates a `file` node whose content lives in `notes/new-thought.md` with no `.text` property, so `lastText` is empty and the second conjunct fails even though the node count rises. Local agent tooling under `.pi/skills/`, not deployed shell; the behavior matches ADR-0004. Suggest a follow-up to assert `last.type === "file" && last.file.startsWith("notes/")`.
- [judgement] `app.js:30-35` — the legacy `demoCanvas` migration-fallback literal still defines `type:"text"` nodes, reachable only via a pre-existing `orbit-canvas-v1` localStorage key. The plan's Maintenance notes explicitly scoped this as out of scope (a legacy-migration decision); a true fresh install uses `createGraphStarterWorkspace()`. The ADR-0004 guardrail says "Balaur's own vaults and authoring paths never produce `text` nodes" — `demoCanvas` is a data literal, not an authoring path, and the hard cut deliberately does not migrate it. Accepted artifact.

### Decision 1 — Note file contract + path convention

- `storage/note-repository.js:42-52,64-76` and `storage/note-catalog.js:16-26,33-51` — spec: "A note is a canonical Markdown file under the `notes/` directory. Identity is the path; there is no mandatory `orbit-id` and no mandatory frontmatter… The note body is ordinary Markdown. Its title is derived, not stored: the first `# Heading` in the body, falling back to the path's slug… Note kind (inbox / reference / AI) is carried by the same inert HTML-comment markers as today… placed at the top of the `.md` body." Implemented exactly: `isNotePath` (`notes/*.md`), `allocatePath` uses `slugify` + `caseFoldKey` + monotonic `-2`/`-3` suffix, `noteTitleFromBody` returns the first `# Heading` else null (catalog falls back to the slug), `deriveKind` reads the three markers, `_noteContent` prepends the marker once. The test asserts the untyped index record (`entityType:null, parseStatus:"ok"`) and the marker-first body bytes. Spec met.

### Decision 2 — Placement/drain API (path-keyed repository; replacePlacement drain primitive)

- `storage/note-repository.js:64-182` — spec: "Introduce one thin note repository modeled directly on the existing task and journal repositories… The repository is path-keyed, not id-keyed… add a placement… remove a placement by `(canvasId, nodeId)`… update a note body… delete a note everywhere (remove every placement referencing the path, then remove the file, then reindex)." All six methods present and shape-correct: `createNote` returns `{path, note, placement}`; `addPlacement` pushes a standard `file` node, re-validates, writes under `stat.hash`, reindexes, reconciles; `removePlacement` filters the node and incident edges; `updateNote` is a full-body rewrite under the expected hash; `deleteNote` resolves placements by catalog scan, removes each, removes the file, `indexer.removeFile`. The regression pin proves placements stay out of the disposable index while drain/delete still resolve them. Spec met.
- `storage/note-repository.js:178-182` — spec: "Expose this as a re-place-by-path operation (remove `(fromCanvas, nodeId)` then add `(toCanvas, path)`), preserving the source path so identity is unchanged… Keep it path-generic." `replacePlacement(path, fromCanvasId, nodeId, toCanvasId, geometry)` removes then adds for the SAME path; the test asserts `result.added.path === path` and `await vault.read(path) === before`. Path-generic and path-keyed. Spec met.

### Decision 4 — AI operator migration

### Decision 5 — Rendering + editing a file-backed note card

## Summary

**Standards: APPROVED.** 10 findings, all `[judgement]`, zero `[hard]`. JSON Canvas stays standards-compliant (only standard `file` nodes, every canvas write re-validates with `isCanvas()`); the AI security boundary is intact (`ai/` unchanged, output rendered escaped); render is synchronous via `NoteCatalog`; writes are canonical-file-first with expected-hash preconditions; the three guard modules and all existing repositories are byte-for-byte unchanged. Worst issues are the `runAICard` legacy-edge accumulation (`app.js:1898`, an accepted hard-cut consequence for unsupported legacy dev vaults) and the `addPlacement` dangling-node gap (`storage/note-repository.js:78`, diagnosed by `NOTE_FILE_MISSING`).

**Spec: APPROVED.** All eight Implementation Decisions are implemented and verified; all twelve user stories addressed; every Out-of-Scope item respected (no `orbit-id` for notes — test-pinned; no note placements in the index — regression-pinned; no auto-migration; no note-rename; goal/habit/project templates are content presets; no 002 concerns). ADR-0004 states all five required points and the four doc files are updated in the same change. The one Spec observation (inspector edits no longer auto-queue AI reruns) is the spec-endorsed consequence of notes mirroring the task/journal editor path (decision 5), not a violation of decision 4. High confidence; the browser-pending behaviors (double-click creates a file-backed note, note edit writes the `.md`, AI operator/output as files, file-backed starter renders, imported `text` nodes render read-only) remain browser-pending per AGENTS.md §13 and are not claimed from the Node suite.
