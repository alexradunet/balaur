# Grill: Declarative Partial Updates adoption → atomic widget source preview

## Decisions made

- **Do not adopt DPU (Declarative Partial Updates).** Its unique capabilities — out-of-order server HTML streaming and declarative `<?marker>`/`<template for>` patching — do not fit Balaur: there is no server (static SPA on GitHub Pages) and the canvas is JS-rendered from in-memory `documentData`, not HTML-streamed. DPU's only remaining contribution would be token-by-token streaming render of a widget preview, which is cosmetic polish over an atomic preview achievable without DPU. Cost (flag-gated Chrome 148, Chromium-only, no polyfill allowed by the no-build/no-CDN rule, plus an envelope variant and feature-detection branches) is disproportionate to that cosmetic value. Adopt only when `stream*` hits Baseline **and** a real user pain demands incremental rendering.
- **Ship the atomic widget source preview**, reusing the existing trusted-document primitive. `buildWidgetDocument(source, {bootstrapSource})` (`widgets/widget-envelope.js`) is a pure string builder that already produces the CSP-meta + bootstrap + source + diagnostic-boundary document and calls `validateWidgetSource` (the scanner). The preview is this construction + a Blob URL + a minimal `<iframe sandbox="allow-scripts" referrerpolicy="no-referrer" loading="lazy">` — the same boundary `Run` uses (`elements/widget-frame.js:166-193`), minus the placement runtime.
- **Explicit "Preview" button**, not auto-run on dialog open. Preserves the §10 explicit-execution posture ("runs only after explicit review and Run"). The scanner gates it inherently: `buildWidgetDocument` throws on scanner failure, so a failing source shows the diagnostic and never builds.
- **Unify the two source-review surfaces into `#widgetSourceDialog`** (`app.js:883`, `showWidgetSourceReview`). Add a live iframe pane + Preview button there. Two entry points open it: (a) a proposal's `widget.create` `<details>` gains a "Preview" button (`operationDescription`); (b) an existing placed widget's "View source" (`balaur-widget-view-source` event) already opens it. No second iframe container; the dialog is the single bounded lifecycle owner.
- **Skip SSE provider streaming.** Cut by user decision. Perceived-latency win on note surfaces is real but not in this scope; the `runRemoteAssistant` plan flow cannot stream anyway (whole-JSON parse required by §6).
- **Do not pull the full `BalaurWidgetFrameElement` into the preview.** It is placement-coupled (MessageChannel init, theme-token projection, heartbeats, `MAX_ACTIVE_WIDGETS = 6` cap, IntersectionObserver, visibility/pause lifecycle). The preview wants none of it. Reuse only `buildWidgetDocument` + `validateWidgetSource`.

## Explicitly ruled out

- **DPU `stream*` JS APIs** (`streamHTMLUnsafe`, `streamAppendHTMLUnsafe`, `setHTMLUnsafe({runScripts})` for incremental streaming): flag-gated Chrome 148, Chromium-only; npm polyfills forbidden by the no-build/no-CDN rule, and the streaming polyfill doesn't stream anyway. Thin value (incremental render) over the atomic preview. Watch only.
- **DPU `<?marker>`/`<template for>` declarative patching in the host document**: no server; host is a fixed SPA shell; card DOM is regenerated by `renderNodes()`, not patched from an arriving HTML stream.
- **DPU route matching** (`@route`, `@navigation`, `:link-to`): Balaur has no URL routing — canvases are sidecar state (`workspace.activeId`), not URLs. View Transitions for portals already work (`app.js:149`, `styles/motion.css`).
- **`patchsrc` fragment includes**: vault is File System Access, not network fetch; widgets run under CSP `connect-src 'none'`.
- **`setHTML` + Sanitizer API hardening of `markdownToHTML`**: `markdownToHTML` (`app.js:843`) is already escape-by-construction (escapes all input, emits only allowlisted tags it generates). Sanitizer is defense-in-depth against a non-existent insertion path, with no Safari. Already deferred on `para/resources/web-platform-2026-07.md` (lines 187, 247). Revisit only if a non-escaped insertion path appears.
- **Token-by-token streaming widget preview**: depended on DPU; cut with it.
- **Keeping widgets / AI-card runtime alive across `switchCanvas()`** (the DPU `contentrevision`/preserve concept): tangential architecture change; today `aiCardRuntime.clear()` on switch is accepted.
- **SSE for any flow**: out of scope this project.

## Edge-case invariants (for the spec to inherit)

- **Teardown**: revoke the preview Blob URL and remove the iframe when `#widgetSourceDialog` closes. Today `showWidgetSourceReview` has no such teardown — this is a new invariant. Prevents orphaned sandboxed execution and Blob leaks. Re-preview re-builds from the current source.
- **No host channel in preview**: skipping the MessageChannel means the bootstrap's `__balaurReportDiagnostic` is a no-op (port null) and no `--balaur-*` theme tokens are projected. The widget runs with fallback styling; preview runtime errors are silent (widget looks broken visually). Full diagnostics and theming come at real `Run` via the full `balaur-widget-frame`. Acceptable for a transient, pre-Apply look.
- **Scanner caps still apply**: `validateWidgetSource` enforces the 128 KiB source / 500 element / 64 KiB script+style limits (`widgets/widget-policy.js`) on preview as on `Run`.
- **Active-widget cap does NOT apply**: the preview is not a placed widget and must not register in `activeWidgets`, so it never evicts a placed widget.
- **Apply is unchanged**: Apply still writes the canonical `widgets/*.html` file inactive (§10). Preview is a read-only live look, not a second path to canonical state.

## Test seams

- **`buildWidgetDocument(source, {bootstrapSource})` and `validateWidgetSource`** are the existing security primitives the preview reuses; the preview adds no new security boundary. The spec should test the *consumer*, not re-test these.
- **`showWidgetSourceReview` / `#widgetSourceDialog`**: the public boundary for the new behavior. Assert: Preview button builds an iframe from the source and it renders without console errors (use `widgets/focus-balaur.html` source as a known-good fixture); scanner-failing source shows the diagnostic and no iframe; Blob URL is revoked on dialog close (no leak / no lingering execution).
- **Proposal `widget.create` `<details>` "Preview" button** (`operationDescription`): opens the same dialog with the model/local source. Assert both local (`proposeLocalWidget`) and remote `widget.create` paths reach the dialog.
- Browser-check skill (`node .pi/skills/browser-check/scripts/browser-check.mjs smoke --offline`) for no-uncaught-errors and dialog-render assertions; manual for scanner-failure and teardown (Blob leak).

## Open questions (deferred)

- **Preview pane layout on narrow screens** (side-by-side vs stacked) — spec/design detail; AGENTS §11 requires narrow-layout inspection. Decided at spec time.
- **Widget-source-text streaming into the `<pre>` (without DPU)** as a later polish if "watch the code generate" is wanted — deferred; visible payoff is thin without the DPU streaming preview this project rules out.

## Summary for downstream

The grill pared "incorporate Declarative Partial Updates" down to a single lean feature: a live, atomic preview of widget source inside the existing `#widgetSourceDialog`, triggered by an explicit Preview button, reused from two entry points (a `widget.create` proposal's `<details>` and a placed widget's "View source"). It reuses the existing security-critical primitive `buildWidgetDocument` (CSP + bootstrap + boundary + scanner) with a minimal `sandbox="allow-scripts"` iframe, and deliberately does not pull in the placement-coupled `balaur-widget-frame` runtime (heartbeats, cap, theme channel). DPU itself, SSE streaming, and the `setHTML`/Sanitizer hardening are all ruled out with reasons recorded. Constraints: revoke the Blob URL on close; preview runs no host channel and no theme tokens (fallback styling); scanner caps still apply; Apply/canonical-write is unchanged.
