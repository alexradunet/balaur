Use BuildContext

Trace context.go from the existing router code to its mounted tree location.

Time: 15 minutes Files: main.dart and balaur_navigation_shell.dart Result: You can select a valid context

Connect context to an element

A BuildContext is a restricted interface to an Element.

Therefore, a context identifies one mounted location in the element tree.

Flutter uses the interface to prevent direct element manipulation.

flowchart LR
    W[Widget description] --> E[Element]
    E --> C[BuildContext interface]
    C --> A[Ancestor lookup]
Key rule: A context belongs to one element location. It is not a reference to the complete application.

Find context in Balaur

The shell route builder receives a context.

ShellRoute(
  builder: (context, state, child) {
    // ...
    return BalaurNavigationShell(
      onSelect: (destination) => context.go(destination.location),
      onToggleTheme: _toggleTheme,
      child: child,
    );
  },
)

The builder context identifies an element below the router service.

The onSelect callback captures this context.

After a navigation tap, the callback calls context.go.

Understand context.go

go_router adds go to BuildContext with a Dart extension.

The method is not part of the Flutter BuildContext interface.

The method finds the router from the current context and changes its location.

flowchart BT
    B[Navigation button element]
    S[Shell route element and context]
    I[Inherited router service]
    R[GoRouter]

    B --> S
    S -->|ancestor lookup| I
    I --> R

The diagram is simplified.

The important direction is upward from the current element to its ancestors.

Trace a settings navigation

sequenceDiagram
    actor User
    participant Topbar
    participant Shell as BalaurNavigationShell
    participant Context as Shell route context
    participant Router as GoRouter

    User->>Topbar: Select SETTINGS
    Topbar->>Shell: Call onNavigate
    Shell->>Shell: Convert name to destination
    Shell->>Context: Call onSelect callback
    Context->>Router: context.go('/settings')
    Router->>Router: Match settings route

BalaurNavigationShell does not own the router.

It sends a selected destination through onSelect.

The route builder owns the navigation action because it has a suitable context.

Compare two contexts

_BalaurAppState.build also receives a context.

@override
Widget build(BuildContext context) {
  return MaterialApp.router(
    routerConfig: _router,
    // ...
  );
}

This context belongs to the BalaurApp element.

The returned MaterialApp.router is below that element.

Therefore, the root context cannot find services that MaterialApp.router provides below it.

flowchart TD
    A[BalaurApp element and context]
    M[MaterialApp router element]
    P[Router provider]
    S[Shell route element and context]

    A --> M
    M --> P
    P --> S

The shell context can search upward and find the router provider.

The BalaurApp context cannot search downward to find it.

Predict the valid context

Which context can correctly call context.go('/settings')?

  1. The context passed to _BalaurAppState.build.
  2. The context passed to the ShellRoute builder.

The ShellRoute builder context is valid.

Its element is below the router provider.

The BalaurApp context is above the router provider.

Use context after asynchronous work

An element can become unmounted while an asynchronous operation waits.

Use context.mounted before you use that context after the wait.

await settingsStore.save(settings);

if (!context.mounted) return;
context.go('/chat');

Do not store a context as a general long-term application reference.

Use the current context during a synchronous operation when possible.
