Lesson 2 | Flutter state

Own state and pass actions

Move the counter button into a stateless child without moving the counter state.

Time: 12 minutes Requirement: Lesson 1 Result: You can pass an action callback

Recall the update process

Answer this question before you change the code.

Which object does setState mark as dirty?

setState marks the Element that is associated with the State object.

It does not mark an immutable Widget as dirty.

Learn the ownership rule

A widget must not own each value that it displays.

Put state in the lowest common parent of all widgets that use or change it.

Pass the current data to child widgets.

Pass callbacks to child widgets that must request changes.

_MyHomePageState
  ├─ owns: _counter
  ├─ passes: current data to Text
  └─ passes: _incrementCounter to IncrementButton

The child can request an increment.

The parent still owns and changes the counter.

This design gives one source of truth.

Household use: A responsibility tile can show a completion value and send an onToggle callback. The shared state owner changes the responsibility.

Create a child widget

Add this class after _MyHomePageState in lib/main.dart.

class IncrementButton extends StatelessWidget {
  const IncrementButton({
    super.key,
    required this.onIncrement,
  });

  final VoidCallback onIncrement;

  @override
  Widget build(BuildContext context) {
    return FloatingActionButton(
      onPressed: onIncrement,
      tooltip: 'Increment',
      child: const Icon(Icons.add),
    );
  }
}

VoidCallback is a Flutter type alias.

It means void Function().

The callback takes no parameters and returns no value.

Pass the parent action

Find the existing floatingActionButton value.

Replace its complete FloatingActionButton with this widget:

IncrementButton(
  onIncrement: _incrementCounter,
)
Important: Pass _incrementCounter without parentheses. This syntax passes the function as a value. The syntax _incrementCounter() calls the function during build.

Test the callback path

  1. Run dart format lib/main.dart.
  2. Run flutter test.
  3. Make sure that the counter test passes.
  4. Change the child value to onPressed: () {}.
  5. Run flutter test again.
  6. Read the failure.
  7. Restore onPressed: onIncrement.
  8. Run flutter test.

The temporary empty callback accepts the tap but requests no state change.

The failing test proves that the callback connects the child event to the parent state owner.

Connect this pattern to the product

ResponsibilityTile(
  isComplete: responsibility.isComplete,
  onToggle: () => completeResponsibility(responsibility.id),
)

The tile receives data and an action.

It does not own the shared responsibility record.

Later, the state owner can call a repository instead of changing a local field.

The tile interface does not need to change.
