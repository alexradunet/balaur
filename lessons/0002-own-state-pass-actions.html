Trace the application root

Use the existing theme control to connect widgets, elements, state, and callbacks.

Start the application

The main function is the application entry point.

void main() {
  WidgetsFlutterBinding.ensureInitialized();
  runApp(
    BalaurApp(
      gateway: OpenAiChatGateway(),
      conversationRepository: InMemoryConversationRepository(),
      settingsStore: SecureProviderSettingsStore(
        const FlutterSecureStorage(),
      ),
    ),
  );
}

ensureInitialized prepares Flutter services before the application uses plugins.

runApp mounts the supplied widget as the root widget.

The BalaurApp constructor receives three service objects.

This technique is dependency injection.

Dependency injection supplies an object with its external dependencies.

Examine the root widget

class BalaurApp extends StatefulWidget {
  const BalaurApp({
    super.key,
    required this.gateway,
    required this.conversationRepository,
    required this.settingsStore,
  });

  final ChatGateway gateway;
  final ConversationRepository conversationRepository;
  final ProviderSettingsStore settingsStore;

  @override
  State<BalaurApp> createState() => _BalaurAppState();
}

BalaurApp is an immutable widget description.

Its three final fields contain configuration values.

The widget creates one _BalaurAppState when Flutter mounts it.

flowchart LR
    W[BalaurApp widget] -->|creates| E[StatefulElement]
    E -->|creates and retains| S[_BalaurAppState]
    S -->|widget property| W
Important: The widget property in _BalaurAppState refers to the current BalaurApp configuration. The associated element maintains this connection.

Separate configuration from mutable state

class _BalaurAppState extends State<BalaurApp> {
  late final GoRouter _router;
  ThemeMode _themeMode = ThemeMode.system;
}
ValueOwnerReason
gatewayBalaurApp widgetA parent supplies this configuration.
conversationRepositoryBalaurApp widgetA parent supplies this configuration.
settingsStoreBalaurApp widgetA parent supplies this configuration.
_router_BalaurAppStateThe mounted application owns its lifecycle.
_themeMode_BalaurAppStateThe value changes while the application operates.

Initialize the router once

Flutter calls initState once after it creates the State object.

The method creates the router and stores it in _router.

The late final declaration permits one assignment during initState.

A theme rebuild does not create another router.

The route builders use expressions such as widget.gateway.

The State object gets the current widget through its associated element.

This design keeps constructor configuration immutable and available to route builders.

Build the application UI

@override
Widget build(BuildContext context) {
  return MaterialApp.router(
    title: 'Balaur',
    theme: BalaurTheme.light(),
    darkTheme: BalaurTheme.dark(),
    themeMode: _themeMode,
    routerConfig: _router,
  );
}

The build method reads _themeMode.

Therefore, a change to _themeMode requires another build operation.

The method returns a new MaterialApp widget description.

Flutter updates the existing elements with the new description.

Trace the theme callback

The router passes _toggleTheme to BalaurNavigationShell.

BalaurNavigationShell(
  onToggleTheme: _toggleTheme,
  child: child,
)

The code passes the function without parentheses.

The navigation shell passes the same callback to BalaurTopbar.

The theme button calls the callback after a tap.

Read setState in context

setState(() {
  _themeMode = isDark ? ThemeMode.light : ThemeMode.dark;
});

The callback changes data in _BalaurAppState.

setState marks the associated StatefulElement as dirty.

Flutter later calls build on this state object.

The new MaterialApp description contains the new theme mode.

Predict a code change

Assume that _toggleTheme changes _themeMode without setState.

What happens after a theme button tap?

The State object contains the new theme mode.

The element does not become dirty.

Therefore, build does not run for this change.

The visible theme stays unchanged until another operation causes a rebuild.

Release the router

@override
void dispose() {
  _router.dispose();
  super.dispose();
}

Flutter calls dispose when it permanently removes the element.

The state object releases the router that it created.

This ownership pair prevents a router resource leak.
