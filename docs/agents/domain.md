# Domain docs

This repository uses one domain context.

## Read before work

1. Read `CONTEXT.md`.
2. Read applicable records in `docs/adr/`.
3. Use the glossary terms in plans, issues, tests, and code.
4. Report conflicts with an architecture decision record.

Missing domain files do not block work.
The domain-modeling skill creates them when decisions require them.

## Layout

- `CONTEXT.md` contains the project glossary.
- `docs/adr/` contains architecture decision records.

Do not replace glossary terms with listed avoided terms.
Record new domain language through the domain-modeling process.
