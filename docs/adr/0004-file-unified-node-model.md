# ADR-0004: File-unified node model

**Status:** Accepted
**Date:** 2026-07-24
**Deciders:** Repository owner
**Reverses:** AGENTS.md §4.2 ("inbox notes and reference pages are standard text nodes")
**Supersedes:** The text-node statements in `docs/generative-canvas.md` ("An AI operator remains a standard JSON Canvas text node"; the AI one-shot note "adds the resulting Markdown as an ordinary JSON Canvas text node")

## Context, decision, and why

Balaur ran two content-node models at once: inline `text` nodes that carry their content inside the canvas JSON (no stable identity, no canonical file, and therefore no placements) and `file` nodes that reference canonical files (placements, repositories, indexing), with notes, inbox captures, reference pages, and AI operator cards as the only inline holdouts; because an inline note has no file to re-place it cannot drain, which blocked the daily-canvas draining queue (project 002) and violated the file-canonical thesis (ADR-0001). The decision is to unify on one model: every content node is a standard JSON Canvas `file` node referencing a canonical `.md`/`.html`/`.canvas`, the canvas document is only space plus edges, `group` (layout) and `link` (external URL) remain because neither is vault content, and inline `text` content authoring is retired. Notes become path-identified `notes/*.md` files with no mandatory `orbit-id` or frontmatter—identity is the path, kind (inbox, reference, or AI) is an inert body marker, and the indexer treats them as valid untyped Markdown—so every authoring template and the double-click-on-background handler become file-creating actions that write the `.md` first and then add a `file`-node placement, exactly as the task and journal repositories already do. As an interop guardrail, `text` remains a valid, rendered, read-only node type so imported and external JSON Canvas 1.0 documents keep working (the shared validator already accepts it), but Balaur's own vaults and authoring paths never produce `text` nodes. Migration is a hard cut appropriate to early development: regenerate the starter and dev vaults rather than auto-rewrite existing inline text nodes, avoiding a dangerous mass-rewrite of user canvases without consent. This meets all three ADR criteria—it is hard to reverse (it changes every authoring path, the AI operator and output storage shape, and the starter), it would surprise a reader without this context (it reverses the long-standing "inbox and reference notes are text nodes" rule), and it is a real trade-off (read-only interop `text` and a hard-cut migration accepted in exchange for one file-canonical model that gives notes placements and drainability)—and it reverses AGENTS.md §4.2 and supersedes the text-node statements in `docs/generative-canvas.md`, both of which are updated in the same change.
