Own state and pass actions

Use this guide when you select the location of UI state.

The rule

Put state in the lowest common parent of all widgets that use or change it.

  • Pass data down through constructor parameters.
  • Pass actions down through callback parameters.
  • Let the state owner make the change.
  • Keep display-only children stateless.
State owner
  ├─ data ───────→ child widget
  └─ callback ←─── child event

Callback types

TypeMeaningExample
VoidCallbackNo parameters and no result.void Function()
ValueChanged<T>One value and no result.void Function(T)
Custom function typeUse it for other parameter or result shapes.Future<void> Function(TaskId)

Selection questions

  1. Which widgets read this value?
  2. Which widgets request a change?
  3. What is their lowest common parent?
  4. Does the value belong only to the current UI session?
  5. Must devices or users share the value?

Use local widget state for temporary UI details.

Use an application state layer for shared household data.

Use a repository or service to save and synchronize persistent data.
