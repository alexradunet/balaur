# Mission: Flutter for a shared household application

## Why
Build a genuinely useful household application for the user and their girlfriend, replacing fragmented coordination with one shared system. The product should run on both partners' phones and on an always-on shared appliance, with an agentic AI interface as its primary interaction model.

## Success looks like
- Ship an installable MVP within two months.
- Two people can use shared household data from their phones and a larger always-on device.
- The MVP supports at least one complete household workflow—capture, coordination, completion, and history—rather than disconnected demos.
- An AI agent can safely help users operate that workflow through a clear, inspectable interface.
- The user can independently design, implement, test, and debug Flutter features across the supported form factors.

## Constraints
- Eight or more learning/building hours per week.
- Ten years of software engineering experience, strongest in JS/TS frontends, .NET backends, and recent agentic engineering.
- Flutter and Dart are new, but introductory programming instruction is unnecessary.
- Initial deployment must cover phones plus an always-on laptop, tablet, or similar device.

## Out of scope
- Feature-complete calendar, habits, responsibilities, cooking, nutrition, pantry, and cleaning systems in the first MVP.
- Teaching general programming or basic frontend concepts already transferable from prior experience.
- Premature multi-platform polish before one end-to-end household workflow is useful.
